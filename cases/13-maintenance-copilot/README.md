# 案例13 · 消防维保工单复用推荐与路由

> 对应《Datawhale FDE 案例 100》NO.13「从纸质流程到数据驱动」· 技术主题：历史复用推荐 / 规则路由 / 轻量数字化
> 方法论标签：最轻量改造（不做大平台）、员工减负与老板透明两头兼顾、避免无效投入

## 业务背景（原案例）

消防维保企业：一线维保大量时间耗在重复填表——某些设备每个月复发同样异常，
月检描述基本是复制上个月；检查记录在纸质表格、维修记录在 Excel、客户信息在
微信里。方案是"最轻量改造"：拥抱已有工具，小模块迭代，而不是再上一套大系统。

## 技术问题

1. 月检描述复用：对 (设备, 本月) 给出"这条大概率还是老毛病"的自动填充建议；
2. 工单路由：设备 → 技能组，对照"全塞综合组"的现状。

## 方案（solution.py）

- `ReuseRecommender`：检索该设备近 6 期历史，异常记录的最常见 (描述, 处置)
  作为建议；统计自动填充命中率与录入字符节省；
- `Router` 三档：v0 全塞综合组 / v1 设备类型→技能组规则 / v2 历史处置多数票校正
  （新设备无历史 → 回退 v1，再无 → 综合组）。

## 实测结果（60 台设备 / 2,400 条历史月检 / 60 条本月待填）

```
月检描述复用：自动填充命中率 77%，录入字符节省 84%（单月省 253 分钟）
工单路由 Top1 准确率：v0 综合组 0% → v1 类型规则 100% → v2 多数票 100%
```

复现：`python cases/13-maintenance-copilot/bench.py`

**结论**：复用推荐把"复制上个月"从人肉动作变成系统默认值（77% 逐字命中、
84% 字符免录入），这与案例"某些设备每个月出现相同异常，AI 可以辅助生成和
调用历史记录"完全对应；路由规则来自历史数据沉淀，新设备自动回退兜底。
边界：仅覆盖"复发型"异常，新异常类型仍需人工填写——这 20% 恰是数据资产
增量的来源。

## 测试

`pytest cases/13-maintenance-copilot` 覆盖：命中率与字符节省阈值、路由层次
（v2 ≥ v1 > v0）、新设备回退不报错、未知设备推荐返回 None、确定性。
