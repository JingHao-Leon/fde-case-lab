# 案例09 · 央企财务报销智能审核（科目映射+双角色复核）

> 对应《Datawhale FDE 案例 100》NO.9「从'表哥表姐'到智能执行」· 技术主题：规则映射 / 双角色交叉复核 / 风险队列
> 方法论标签：AI 判断 + 监督兜底、确定性业务直通、破冰项目先摘最近的桃子

## 业务背景（原案例）

央企科研机构：报销一张发票，财务要判断费用性质、关联出差申请/审批/项目、再
手工录入集团系统，完整流程半个月到一个月；AI+RPA 后 1~2 天，落地 10 个场景。
架构精髓：**AI 负责判断，监督机制兜底，RPA 负责执行**——确定单直通，
人只处理风险。

## 方案（solution.py）

- `SubjectMapper` 科目映射规则引擎（规则表外置，财务可维护、可解释）；
- `DualReviewer` 双角色交叉复核：执行角色查招待费审批/住宿标准/发票重复，
  监督角色独立复核科目错配；两角色一致且无风险 → **自动直通**，
  任一发现问题 → 风险队列转人工；
- 判定纪律：**误放（有问题却直通）= 0 是红线**，直通率是换来的副产品。

## 实测结果（2,000 张报销单，植入问题单 75 张）

```
科目映射准确率：100.0%（规则引擎）
自动直通率：    78.0%
问题检出率：    100.0%（75/75）
误放：          0 张（红线）
折算：人工 8 分钟/张 → 人工只需审 441 张风险队列单据
```

复现：`python cases/09-finance-audit/bench.py`

**结论**：78% 的确定性单据直通、75 张问题单 100% 进风险队列且零误放——
复现了原案例"AI 处理确定性工作，人只处理风险与异常"的分工。本实现未含
RPA 执行环节（数据不出域的私有化部署与集团系统录入在真实项目中是另两个
独立工程）。

## 测试

`pytest cases/09-finance-audit` 覆盖：科目映射准确率 ≥99%、零误放红线、
检出率 ≥95%、直通率区间、重复发票硬拦截、确定性。
