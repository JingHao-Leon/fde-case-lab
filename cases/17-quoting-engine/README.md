# 案例17 · 非标制造售前报价引擎（成本模型+校准飞轮）

> 对应《Datawhale FDE 案例 100》NO.17「从老师傅报价到AI深度协同」· 技术主题：成本建模 / 残差校准回归 / 数据飞轮
> 方法论标签：AI 只做结构化、报价回到企业自己的规则库、人工校准回填、置信分流降工作量

## 业务背景（原案例）

两三百人的柔性制造企业，非标订单报价链路 = 图纸解析 → 需求拆解 → 工艺判定 →
成本核算 → 报价，全靠老师傅；响应慢（询价卡几天丢单）、报错价直接吃掉利润。
关键教训：端到端让模型直接出价对不上真实成本——**模型只负责结构化，报价必须
回到企业自己的物料和规则库**，再由人工校准回填形成数据飞轮。

## 技术问题

报价一致性（对隐性真实成本的 MAPE）与人工工作量（结构化置信分流后的送审比例）。

## 方案（solution.py）

- `ExpertQuote` 老师傅基线：「材料×工艺」分组的"材料费按重+加工费按件"线性心算
  ——批量折扣、表面处理、费率浮动全靠均摊；
- `RuleQuote` 企业规则库：显式参数（库内材料价/标准工时/费率/折扣/管理费率）
  逐项核算，可解释可复用，但参数与真实世界有系统性偏差（库没跟上市场）；
- `CalibratedQuote` 数据飞轮：用 k 条人工校准后的报价做岭回归残差修正
  （特征 = 规则库成本 + 工艺哑变量 + 公差 + 数量^−0.5）；
- `human_review_ratio`：置信分流——人工只审低置信字段。

## 实测结果（600 条历史询价，450 条测试）

```
方案                  对真实成本 MAPE
老师傅快速估法(基线)        58.4%
规则库成本模型              13.2%
飞轮 k=30                 13.9%
飞轮 k=80                  9.9%
飞轮 k=150                 9.2%
```

复现：`python cases/17-quoting-engine/bench.py`

**结论**：显式成本模型直接把 MAPE 从 58.4% 打到 13.2%——"把老师傅脑子里的账
变成企业数据资产"本身就是最大收益；数据飞轮再降 30% 到 9.2%，且校准样本越多
越准（k=30 时 13.9% ≈ 裸规则库，说明飞轮需要最小样本量，冷启动要靠规则库）。
注意 k=30 略差于规则库是真实规律：小样本校准会过拟合，这也解释了原案例
"前两个月一直在磨合微调"。响应时间从"卡几天"到毫秒级，送审字段占比 <50%
对应"相关工作量减少 50%+"。

## 测试

`pytest cases/17-quoting-engine` 覆盖：模型优于常数基线、飞轮显著优于裸规则库、
校准样本量单调收益、阶梯报价单价单调不增、送审比例 <50%、确定性。
