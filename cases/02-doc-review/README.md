# 案例02 · 车管所网办材料审核（规则引擎+置信度分流）

> 对应《Datawhale FDE 案例 100》NO.2「从人工审材料到自动化办件」· 技术主题：规则引擎 / 交叉校验 / Human-in-the-loop 分流
> 方法论标签：从运维小切口进场、把 AI 嵌回业务流程、暴露"人工放宽"交甲方决策

## 业务背景（原案例）

群众在线提交身份证、合同、发票、营业执照等图片材料，人工逐张打开审核+录入：
单件约 15 分钟、日均 700~800 件。AI 化后单件 3~5 分钟、日均约 1100 件，材料
识别率半年内从 70% 多磨到 98%。案例最有价值的转折：自动化把过去人工审核里的
"放宽"暴露了出来——尺度问题的最终决策权必须交还甲方。

## 技术问题

办件级自动审核：材料齐全性 → 字段完整性 → 证照校验位 → 跨材料一致性 →
有效期 → **置信度分流**（低置信材料转人工，硬错误直接拒绝）。
评价口径以政务红线优先：漏放（有缺陷却自动通过）必须为 0。

## 方案（solution.py）

- `ReviewEngineV1` 基础规则：必需材料齐全 + 必填字段非空（最小可上线版本）
- `ReviewEngineV2` 交叉校验版：
  - R2 身份证/信用代码校验位（GB 11643 加权因子）
  - R3 跨材料姓名一致性（身份证 vs 合同/发票当事人）
  - R4 成交金额一致性——只比对带 `deal` 标记的成交类材料
    （保单、还款证明金额语义不同，参与比对会大量误拦，这是数据建模的关键细节）
  - R5 有效期；R6 置信度分流：仅低置信 → review（人工只看问题材料）
- `conf_human` 阈值可配置，对应"识别率打磨 → 转人工率下降"的迭代过程

## 实测结果（2,000 办件，419 个带缺陷）

```
引擎                       审核准确率  自动通过率   漏放   误拦   折算日产能*
V1 基础规则(齐全性)           84.2%     79.0%    317     0     4706件
V2 交叉校验+置信分流         100.0%     59.5%      0     0      477件
V2+识别率打磨(+0.12)        100.0%     62.5%      0     0      523件

人工基线：32 件/日（单人 15min/件、8h 工作日）
```

\* 产能折算只计"审核+复核"环节；原案例 1100 件/日还叠加 RPA 自动填单与系统流转。

复现：`python cases/02-doc-review/bench.py`

**结论**：V1 的 79% 自动通过率是陷阱——漏放 317 件（fa_rate 76%）在政务场景
一票否决。V2 用自动通过率换来 100% 准确率、零漏放零误拦，单人折算产能仍是
人工的 ~15 倍；识别率打磨（置信度整体上移）再把产能买回来。这复现了原案例的
核心判断：识别率是"一点点磨出来的"，而审核尺度问题要交还业务方决策。

## 测试

`pytest cases/02-doc-review` 覆盖：校验位算法、V1 必漏放而 V2 零漏放（红线断言）、
V2 零误拦、自动通过覆盖率、判定理由可解释性、审计确定性。
