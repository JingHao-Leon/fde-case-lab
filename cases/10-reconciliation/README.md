# 案例10 · 线下零售智能对账（多级模糊匹配）

> 对应《Datawhale FDE 案例 100》NO.10「从人工核对到智能对账」· 技术主题：记录链接 / 容差匹配 / 差异分类
> 方法论标签：选"正反馈最快"的第一单、容忍区间里被放弃的收入、人工只处理真差异

## 业务背景（原案例）

线下零售企业资金结算链路：门店收银系统一套数据，商场结算一套数据，每周期人工逐笔
核对，一个周期 1~2 个人天。更关键的是总部因此设了"差异容忍区间"——差异在 1~3 个
百分点内就不追了，**被放弃的不只是人工，还有真金白银**。

## 技术问题

两套异构流水做记录链接（entity resolution），并把差异**正确分类**：漏记 / 金额漂移 /
单号转录错误 / 拆单 / 多记——分类对了，净差异金额才可信，追讨才有依据。

## 方案（solution.py）

- `ExactMatcher`：单号精确 join（对应对账员"先划掉对得上的"）。剩下的差异全部
  粗分为"漏记/多记"，金额还原误差大。
- `FuzzyReconciler` 四级流水：
  - **L1** 单号精确 + 金额一致；
  - **L2** OCR 混淆抢救：等长且仅 1 位差异（0↔8、1↔7、5↔6…）且金额一致；
  - **L3** 同店金额贪心一对一配对（±容差）→ 标记金额漂移；
  - **L4** 双指针找"两笔商场 = 一笔 POS"→ 拆单；其余归漏记/多记。
  人工只复核带标签的真差异。

## 实测结果（30 店 / 17,100 笔 POS，植入差异 1,013 笔）

```
方法                  分类召回   OCR抢救   判漏记   判多记   净额误差(元)    耗时
精确匹配(第一轮人工划账)   0.0%       0    1147     624    40805.13      8ms
多级模糊匹配(Fuzzy)     70.9%     274     429     151     2543.18    6323ms
```

复现：`python cases/10-reconciliation/bench.py`

**结论**：多级模糊匹配把净差异还原误差从 4.08 万元压到 **0.25 万元（-93.8%）**，
1,013 笔植入差异中 70.9% 被正确分类（OCR 抢救 274 笔），6.3 秒完成 vs 人工逐笔
约 100 分钟。精确匹配并非无用——它是第一轮"划账"，把 94% 的正常流水先清掉，
模糊引擎只在 4%~6% 的残差上工作，这正是原案例"AI 先做第一轮、人处理真差异"的
分工方式。剩余 ~29% 未正确分类主要是漂移金额超出 ±5 元容差与拆单碎片，可通过
分位数自适应容差继续优化。
