# 案例03 · 诉讼案件时间线重建与时效检查

> 对应《Datawhale FDE 案例 100》NO.3「从案头工作到智能协作」· 技术主题：事件时间线重建 / 相对日期解析 / 诉讼时效规则
> 方法论标签：律师保留策略判断、先建案再交互、隐性经验结构化（时效中断规则）

## 业务背景（原案例）

商事诉讼律师的材料整理动辄 3~5 个工作日；14 被告的请求权基础分析要 2~3 天，
AI 辅助下一晚完成；100 万字案件一天完成全案梳理（效率 +70%）。律师的产能瓶颈
不在专业判断，而在信息处理。

## 技术问题

从案件事件流中重建**时间线**并判定每项请求权的**诉讼时效状态**：
- 口语化时间（"去年下半年""3 个月前"）按基准日解析；
- 起算点 = 约定履行期届满日（无则取违约日）；
- 届满后的催告 / 对方承认构成**时效中断**，自中断日重新起算；
- 输出 时效内 / 临近时效（6 个月内到期）/ 已过时效 + 依据链。

## 实测结果（20 案件 / 557 条事件 / 54 项请求权）

```
时效判定一致率（vs 逐条 gold）：96.3%（52/54）
时效状态分布：时效内 57 / 已过时效 2 / 临近时效 1
时间线排序正确率：20/20 案件全对
```

复现：`python cases/03-case-timeline/bench.py`

**诚实边界**：未命中的 2 条来自口语月份取整误差（"3 个月前"按 90 天估算与
真实日期的偏差跨越了状态边界），生产系统应对边界附近日期取"最早可能日/最晚
可能日"输出区间而非单点。时间线排序与中断重算逻辑全部正确。

## 测试

`pytest cases/03-case-timeline` 覆盖：口语日期解析、时间线排序与当事人清单、
中断重算（起算点晚于届满日）、时效判定一致率 ≥90%、确定性。
