# 案例01 · 制造经验传承知识库（检索质量评测）

> 对应《Datawhale FDE 案例 100》NO.1「从师徒带教到AI辅助培训」· 技术主题：中文检索 / BM25+TF-IDF 混合 / 词表归一化 / 检索评测
> 方法论标签：新人高频问题直接变成测试集、验收标准与客户共定（≥80%）、AI 进入原有培训流程

## 业务背景（原案例）

德国零部件制造企业，工艺参数、材料配比、设备状态处理等隐性经验掌握在老师傅手里，
新人培养两三个月。原案例的验收方式很有 FDE 特色：**新人高频问题直接变成知识库
测试集**，文档解析率约 95%、问题召回片段准确率 ≥80% 达标才算技术通路跑通。

## 技术问题

口语化新人提问（"316L 锻打要烧到多少度"）与书面经验卡（"316L不锈钢·锻造·温度：
加热温度控制在 1150-1200°C…"）之间存在**词汇鸿沟**。回测四种检索方案，
检验哪一种能过 80% 验收线。

## 方案（solution.py）

| 方案 | 思路 |
|---|---|
| `KeywordSearch` | 字面字符重合度打分（对应"随手做关键词搜索"的现状基线） |
| `TfidfSearch` | 字符 n-gram (2-4) TF-IDF + 余弦（中文免分词标准做法） |
| `HybridSearch(裸)` | BM25(char-bigram) × 0.5 + TF-IDF × 0.5 融合，可选 MMR 去冗余 |
| `HybridSearch + GlossaryNormalizer` | 领域词表把别名归一到书面称谓，query/doc 同侧归一化后再混合检索 |

`GlossaryNormalizer` 对应的是 FDE 的真实工作量：把"同一个工艺的不同叫法对上号"
（锻打=锻造、调质=热处理、烧到多少度=温度）。数据生成器按 95% 解析率模拟
OCR 入库噪声，检验带噪鲁棒性。

## 实测结果（240 张经验卡 / 240 条高频问题）

```
方案                干净 Recall@5    Top1   MRR@10   带噪 Recall@5
关键词搜索(现状)         66.2%     33.3%   47.2%        65.4%
TF-IDF(裸)              53.3%     19.6%   34.5%        52.1%
混合检索(裸)             55.8%     22.5%   38.1%        55.4%
混合+词表归一化          99.2%     90.8%   94.2%        97.1%
```

复现：`python cases/01-knowledge-base/bench.py`

**结论**：换检索器（TF-IDF、混合）在词汇鸿沟面前几乎无效甚至更差——
**第一杠杆是词表归一化**（66.2% → 99.2%，带噪仍 97.1%），算法排第二。
负结果值得记录：裸混合检索（55.8%）反而低于关键词基线，因为融合拉平了
区分度不足的分数。这与案例 8「把同一个物料的不同叫法对上号」的结论互相印证。

## 测试

`pytest cases/01-knowledge-base` 覆盖：排序良构性、80% 验收线断言、
归一化 > 裸混合 > 关键词的层次关系、95% 解析率噪声鲁棒性（≥70%）、
MMR 降低同前缀冗余且不挤掉首位、评测确定性。
