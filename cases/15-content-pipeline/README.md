# 案例15 · 本地生活短视频脚本量产流水线

> 对应《Datawhale FDE 案例 100》NO.15「从经验写稿到稳定量产」· 技术主题：参数化生成 / 校验器链 / Human-in-the-loop 回退
> 方法论标签：把运营经验拆成业务字段、AI 先跑人判断、不合格回退、反馈调优

## 业务背景（原案例）

抖音本地生活代运营，高峰一天要 200~300 条文案；好的文案靠少数运营，无法规模化。
直接让 AI 写：不同商户差异照顾不到、"AI 味"重。解法是把生产流程拆开：
字段化输入 → 参数化生成 → **多级校验** → 不合格重写 → 仍不合格回退人工。

## 技术问题

在保证"可用率"（长度/违禁词/卖点覆盖/结构/查重五关全过）的前提下把人工从
"写"退到"审"，支撑高峰期日产 200~300 条。

## 方案（solution.py）

- `NaiveWriter` 基线：单模板硬填、卖点复读、部分脚本夹带违禁词——复现"直接
  让 AI 写"的合规与质量问题；
- `Pipeline`：钩子(5)×细节(6)×推荐语(5)×CTA(4) 组合生成，语气随商户风格参数；
  校验器链：口播长度(120~220 字) → 违禁词(广告法绝对化用语) → 核心卖点覆盖 →
  结构完整 → 同商户 4-gram 查重；未过换模板重写一次，仍未过进人工队列；
- `audit_texts`：同一套校验器公平评估任意来源脚本的可用率。

## 实测结果（320 条文案任务 / 40 家商户）

```
生产方式              一次可用率   人工耗时/条   单人日交付
人工写作(现状)           100%      24.0min      20条
直接AI写(基线)             0%       4.2min     114条
流水线+校验+回退          100%       1.2min     400条
```

复现：`python cases/15-content-pipeline/bench.py`

**结论**："直接 AI 写"一次可用率为 0——违禁词（广告法绝对化用语）、卖点缺失、
同商户撞模板是三大硬伤，人工修改耗时反噬产能；流水线用校验器把这些问题在
机器侧吸收（含一次重写机会），人工只做 1 分钟抽检，单人日交付 400 条 ≥
案例高峰需求的 200~300 条。这里复现了原案例的核心判断：**"写出一篇文案"和
"稳定生产可用脚本"是两回事**——Know-how 沉淀为字段与校验规则才能量产。

## 测试

`pytest cases/15-content-pipeline` 覆盖：基线复现违禁词问题、流水线输出零违禁词、
终过率 ≥95% 且回退率 ≤5%、流水线显著优于基线可用率、同商户脚本不重复、
极端输入进人工队列、确定性。
