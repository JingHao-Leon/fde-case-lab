# 案例05 · TikTok 达人建联匹配与履约提醒

> 对应《Datawhale FDE 案例 100》NO.5「从大海捞针到全链路提效」· 技术主题：匹配排序 / NDCG 评测 / 状态机与 SLA 提醒
> 方法论标签：AI 先筛人再沟通（高价值达人商务留给人）、状态机自动提醒替代人工翻表、统一数据漏斗

## 业务背景（原案例）

头部电商的 TAP 达人建联业务三难：找人难（大海捞针）、匹配难（上万选品池）、
履约慢（平均 30 天，运营天天人工"催"）。AI 改造边界清晰：**匹配名单和履约提醒
交给 AI，真正与达人的沟通留给人**。

## 技术问题

1. 匹配排序：把"什么商品推给什么达人"变成可评测的排序问题（NDCG@10）；
2. 履约提醒：状态机（建联→寄样→收样→创作→提交）+ 各状态 SLA → 每日待办清单，
   对照人工翻 Excel 的漏催率，并回测提醒覆盖对履约周期的影响。

## 方案（solution.py）

- 三档排序器：`FollowersRanker`（人工现状：粉丝量降序）、`RuleRanker`
  （类目+转化率+响应率）、`MatchRanker`（类目 × 卖点标签重叠 × 黄金粉丝段
  1万-50万 × 转化率 × 响应率）；
- `ReminderEngine`：状态停留超 SLA（建联3天/寄样4天/收样3天/创作7天）→
  今日待办按逾期天数排序输出；
- 双组回测：manual 组（人工抽查 30% 提醒覆盖）vs system 组（85% 覆盖）。

## 实测结果（500 达人 / 30 个评测商品 / 120 条 30 天履约轨迹）

```
匹配方案               NDCG@10   HitRate@10
粉丝量降序(人工现状)      0.4%      0.7%
类目+转化率规则          56.0%     52.3%
标签×粉丝段×转化率       90.3%     87.3%

漏催次数：人工翻表抽查 162 次 vs 系统提醒 0 次
平均履约周期：低提醒覆盖 14.6 天 vs 高提醒覆盖 9.6 天（-34%）
```

复现：`python cases/05-influencer-crm/bench.py`

**结论**：粉丝量排序基本等于随机（NDCG 0.4%）——"达人挑贵的"是直觉陷阱；
加入标签×粉丝段×转化率后 NDCG 达 90.3%。提醒全量覆盖消灭漏催，履约周期
-34%，方向与案例"30 天 → 18 天"一致（真实系统中还叠加寄样物流等环节）。
边界：高价值达人的商务沟通保留人工（案例原话：一句话说错的损失远超自动化收益）。
