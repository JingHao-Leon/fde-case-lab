# 基于 Datawhale FDE 案例 100 的可行 AI Skill 研究

> 研究问题：如果参照 [FDEOps](https://github.com/suboss87/FDEOps) 的做法，
> 把《Datawhale FDE 案例 100》（24 个真实企业落地案例）中的 FDE 方法论
> 提炼成 AI 编码代理可安装、可执行的 **Skill**，哪些是可行的？可行到什么程度？
> 本文给出全量 24 案例的映射、可行性评分与分级结论；
> 已实现为 SKILL.md 的技能见 [skills/](./) 目录。

## 一、可行性评估框架

一个案例能否提炼成 Agent Skill，按 5 个维度打分（0~5）：

| 维度 | 含义 | 案例中的对应判断 |
|---|---|---|
| **规则明确度** | 判断标准能否写成可执行规则 | 案例反复强调"确定规则交给系统，判断留给人"（02/09/21） |
| **数据可得性** | 输入数据是否存在于既有业务系统 | "数据能不能拿出来，往往才是真正的门槛"（08/22） |
| **验收可量化** | 能否定义回测/验收指标 | "新人高频问题直接变成测试集"（01）、"效果基线先行"（22） |
| **人机边界清晰度** | 人保留什么决策、AI 承担什么执行 | "AI 生成、人决策"（21）、"识别出来以后怎么办交甲方"（02） |
| **跨案例复用度** | 同一技能出现在多少个案例中 | 审核分流至少出现在 4 个案例（02/09/19/10） |

**总分 ≥ 20 → 一级（直接可安装执行）**；15~19 → 二级（可安装，需人工关键节点）；
10~14 → 三级（研究性，仅提供参考实现）；< 10 → 不做成 skill（纯组织/人际工作）。

## 三、结论：10 个可安装 Skill + 5 个候选

**一级（本文档随附 SKILL.md，均有本仓库可运行代码作为参考实现）：**

| Skill | 覆盖案例 | 参考实现 | 核心验收指标 |
|---|---|---|---|
| `fde-discovery` | 02/08/13/20 的第一步 | —（访谈引导，产出结构化问题定义） | 问题定义可追溯率 |
| `kb-build` | 01/11 | cases/01 | Recall@5 ≥ 80% 验收线 |
| `doc-review` | 02/09/19 | cases/02, cases/09 | 误放 = 0（红线）+ 直通率 |
| `record-link` | 08/10 | cases/08, cases/10 | 净差异还原误差 / 重复拦截误报 = 0 |
| `state-reminder` | 05/13/22 | cases/05 | SLA 漏提醒 = 0 |
| `recon-chain` | 20 | cases/20 | 四类异常检出、证据完整 |
| `cost-quote` | 17/23 | cases/17 | 报价 MAPE + 校准样本单调收益 |
| `content-pipeline` | 12/15 | cases/15 | 一次可用率 + 违禁词零容忍 |
| `semantic-layer` | 16 | cases/16 | 同题重复执行一致性 = 100% |
| `timeline-check` | 03 | cases/03 | 时效判定一致率 + 排序正确率 |

**二级（SKILL.md 附参考实现链接，执行需人工关键节点）：**
`site-screen`（04）、`load-optimize`（06）、`inventory-ads`（22/24）、
`data-audit`（24）、`spec-geometry`（21，规范全量条文工程量大故降为窄域）。

**不做成 skill 的工作**（案例 07/14/18 的核心）：业务陪跑、一把手推动、
组织与 KPI 调整——这是 FDE 的人格化职责，Agent 只能做会议纪要与待办跟踪，
强行做成 skill 会重蹈案例 04 批评的"为多智能体而多智能体"。

## 四、跨案例方法论（所有 SKILL.md 的公共骨架）

从 24 个案例中提炼出 5 条反复出现的 FDE 工作纪律，写入每个 SKILL.md 的
"边界"一节：

1. **先定义验收，再写实现**（01/08/22）：指标与客户共定，技能自带指标模板；
2. **确定性优先**（16/02）：能写规则的不用模型，模型输出必须可审计；
3. **零误放/零误拦红线**（02/09/08）：宁多人工复核，不放错误进生产；
4. **保留人的决策权**（05/17/21）：商务沟通、最终签核、专业责任不自动化；
5. **数据先行**（08/22/24）：数据拿不出来，一切白搭——技能第一步都是
   "数据可得性检查"。

## 五、与 FDEOps 的关系

FDEOps 把技能组织为客户接洽的六阶段（Land→Discover→Plan→Ship→Outcome→Close），
是**流程轴**；本研究按**能力轴**提炼（一类可复用的判断/执行能力），
两者正交：例如 `doc-review` 属于 Ship 阶段的交付技能，`fde-discovery`
属于 Discover 阶段。安装方式参照 FDEOps：把对应 SKILL.md 放入
agent 的技能目录即可（Claude Code / Cursor / Codex 通用）。
