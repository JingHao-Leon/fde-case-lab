# Record Link · 实体归一化与记录链接

对应案例：NO.8（ERP 物料查重）、NO.10（商场对账）。
参考实现：`cases/08-material-search/`（查重误报 0；真实 Amazon-Google 标注
基准 Top1 67.9% vs 基线 4.3%）、`cases/10-reconciliation/`（净额还原误差 -93.8%）。

## 何时使用

- "找不到物料 → 重复录入 → 买错买重"的循环要切断
- 两套系统的流水要逐笔对账并**分类**差异（漏记/漂移/转录错误/拆单/多记）
- 跨平台商品/SKU 要做实体匹配

## 流程

1. **归一化优先（第一杠杆）**：全半角、单位后缀、旧编码、别名映射、NFKC；
   query 与文档同侧归一化。规则表外置可维护。
2. **精确键第一道闸**：归一化键完全相等 → 自动判定（查重场景：拦截）。
   自动动作必须零误报——拿不准的进人工。
3. **模糊候选第二道闸**：字符 n-gram TF-IDF/BM25 混合检索取 Top-K，
   命中要过业务规则（品牌一致、规格字段精确相等——案例 8：品牌不同≠重复）。
4. **对账差异分类**：L1 精确 join → L2 OCR 形近字抢救（等长 1 位混淆）→
   L3 同店金额贪心配对 → L4 双指针找拆单；余下才标漏记/多记。
5. **净额还原**：输出净差异金额与分类明细——分类对了，追讨口径才可信。

## 验收

- 干净数据零误报（自动动作）
- 植入差异的分类召回 ≥ 70%，净额还原误差有界（案例 10：-93.8%）
- 在真实标注基准（如 Amazon-Google）上有对照成绩

## 边界

- 判"是同一实体"之后怎么办（删除/合并/追讨）是业务决策，技能只给证据
- 金额容差、品牌规则等必须与客户共定并写入配置
