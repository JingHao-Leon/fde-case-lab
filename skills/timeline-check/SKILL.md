# Timeline Check · 时间线重建与期限检查

对应案例：NO.3（诉讼律师案件处理，材料整理 3~5 天 → 一晚）。
参考实现：`cases/03-case-timeline/`（时效判定一致率 96.3%）。

## 何时使用

- 案件材料上千页、事件分散在聊天记录/合同/凭证里，人工整理按天计
- 需要逐项检查期限状态（诉讼时效 3 年、履约期、质保期、审批时限）
- 开庭/截止在即，需要快速恢复"案件全貌"

## 流程

1. **事件抽取**：从材料中提取事件（类型/日期/主体/金额），口语化时间
   （"去年下半年""3 个月前"）记录锚点，按基准日解析为**日期区间**
   而非单点——边界附近的期限结论要给"最早/最晚可能"两档。
2. **时间线排序**：按解析日期排序，输出当事人清单与事件轴；
   排序正确率要求 100%（时间线是后续一切判断的底座）。
3. **期限规则表**：期限类型 → 起算点 → 时长 → 中断/顺延事由，
   全部外置成规则（如诉讼时效：起算=履行期届满，催告/承认构成中断并
   自中断日重算）。规则表由专业人士审核后固话。
4. **逐项判定**：每项请求权/义务输出 状态（内/临近/已过）+ 依据链
   （起算日、中断次数、届满日），临近到期（默认 6 个月）提前预警。
5. **人工确认**：判定结果供律师/法务复核，策略与责任永远在人
   （案例 3：AI 负责信息处理，律师负责判断与专业责任）。

## 验收

- 时间线排序正确率 100%
- 期限判定与人工标注一致率 ≥ 90%，不一致项全部给出区间解释
- 每个判定附可追溯依据链

## 边界

- 不生成诉讼策略、不定性责任——那是律师的专业判断
- 期限规则按司法辖区维护，规则表更新需专业人士确认
